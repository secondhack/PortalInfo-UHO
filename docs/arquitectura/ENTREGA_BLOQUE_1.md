Modelos de contenido, encuestas, aprobaciones, notificaciones y analítica preparados.
2. **Archivos principales:** backend/config/settings.py y urls.py; modelos de las ocho apps backend/apps; accounts/providers.py, permissions.py, serializers.py y tests.py; frontend/src/api/client.js, contexts/Auth.jsx, layouts/Admin.jsx, pages/Resource.jsx, Settings.jsx, Dashboard.jsx y routes/App.jsx; migraciones, scripts Windows, Dockerfiles/Compose y documentación obligatoria.
3. **Migraciones aplicadas:** accounts, catalogs, content, approvals, notifications, analytics, audit y settings_app, cada una 0001_initial; además 15 migraciones Django (auth/contenttypes/sessions). Total 23, sin cambios pendientes. Clúster separado 127.0.0.1:55432, base portalinfo.
4. **Pruebas:** 24 Django/PostgreSQL y 6 React aprobadas; 0 fallidas en ejecución final. OpenAPI válido, pip check correcto, seed idempotente y smoke HTTP correcto. Evidencia y límites en ../pruebas/RESULTADOS.md.
5. **Problemas:** descargas interrumpidas, caché npm restringida, sandbox Windows para pg_ctl/esbuild, puertos ocupados y DEBUG heredado. Resueltos para ejecución local; no se modificaron los otros proyectos/servidores ni los documentos originales.
6. **SRS:** inventario completo RF-01–RF-61 y RNF-01–RNF-23 en TRAZABILIDAD.md. Registro previo, logout, bloqueo, asignaciones, nomencladores y configuración administrativa implementados. AGA_AUTH y obtención de perfiles institucionales pendientes por diseño demo. Los requisitos editoriales, portal, notificaciones y analítica conservan estado parcial/pendiente. No se declara verificado un requisito integral por pruebas de una sola parte.
7. **Comandos desde la raíz:** `scripts\start-database.cmd` si el clúster no está activo; en terminales separadas `scripts\start-backend.cmd` y `scripts\start-frontend.cmd`. Equivalentes: `.venv\Scripts\python.exe backend\manage.py runserver 127.0.0.1:8010` y `npm.cmd --prefix frontend run dev`. UI http://127.0.0.1:5174, Swagger http://127.0.0.1:8010/api/docs/.
